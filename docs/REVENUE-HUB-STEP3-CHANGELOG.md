## Behavioral changes

- KPI cards now render metric-specific `Analyze [metric]` and `How to use [metric]` controls from v2.
- KPI guidance is generated by the UI-only `buildMetricGuidance()` function.
- KPI clicks are handled through one listener on `#kpi-grid` in the normal bubble phase.
- KPI prompt construction now routes through `buildPromptContext()` and model formatting through `formatPrompt()`.
- The existing non-metric prompt content for program, cadence, diagnostic, resource, and role learning is preserved.
- The role prompt path is explicit rather than relying only on fallback behavior.
- The metric prompt is enriched with upstream/downstream evidence, non-skill causes, first-leak investigation, owner/SLA, measurement window, and falsification requirements.
- Former v2 runtime fix styles and the consolidated KPI guidance styles now live in `revenue-performance-v2.css`.
- Selected role cards keep readable text in dark mode instead of allowing the description to be overridden by a low-contrast color.
- Revenue Hub secondary controls now have explicit readable hover states and visible keyboard focus treatment.
- Dark-mode card metadata uses the stronger shared muted-text token for better readability.
- The desktop Page Guide now opens beside the fixed toggle, stays vertically centered, and scrolls within the viewport rather than extending off-screen on shorter displays.
- The v3 hero sizing guard now lives in static `revenue-performance-v3.css`; the runtime `<style>` injection was removed.
- Page Guide active links now expose `aria-current="location"`.
- v4 remains present and v3 still dynamically loads it. No deletion is authorized yet.

## Automated result to date

The Revenue Hub smoke workflow completed successfully after the Step 3 JavaScript/CSS consolidation. Additional CI guardrails now verify that the v3 visual QA layer does not reintroduce runtime style injection and that the focus/active-state CSS remains present.
